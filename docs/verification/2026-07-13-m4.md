# M4 workspace evolution verification — 2026-07-13

## Scope

- W4.1 advanced layout: canvas, per-device geometry, focus, sidecar, second monitor, pop-out, drag, resize and layer order.
- W4.2 organization: folders, tags, archive, screen search, personal templates and reference packs.
- W4.3 tools: cross-screen content search, capture promotion, richer notes, presets, notifications, typed tables/CSV and Resource Counter.
- W4.4 distribution: PWA/offline shell, storage quota, density, accent themes, EN/IT shell and cloud-sync design gate.

- `npm run build`: pass.
- `npm run lint`: pass.

WebKit remains a CI-only gate on this workstation because its Linux runtime dependencies require system packages unavailable in the current environment. This is the same documented host constraint as M3, not an application failure.

## Browser evidence

The local app and the production preview were inspected in the in-app browser using live DOM and computed-style assertions.

- Canvas mode exposed one drag handle per tool, native continuous resize and device geometry controls including layer order.
- Focus reduced the workspace to one tool and returned to the previous layout.
- Sidecar removed the selected tool from the main canvas and rendered it in a dedicated complementary region.
- At `390×844`, the active canvas selected the `mobile` geometry profile and global horizontal overflow remained zero.
- EN/IT, compact density and Forest accent persisted after reload; the document language, density data attribute and computed accent changed accordingly.
- Screen management exposed folders, tags, archive, search and personal template controls; saving a personal template produced a reusable library entry.
- The production preview exposed the manifest and theme metadata and loaded without application console errors. The service worker and runtime cache are present in the production build.

## Deliberate gates

- Cloud sync transmits no data. The threat/conflict model must pass privacy, revocation, conflict and deletion tests before a provider can be implemented.
- The WebView route is evaluated in `arcana-screen/docs/MOBILE_WRAPPER.md`; no placeholder store binary is shipped without real device and ownership gates.
- Product acceptance still requires observed DM sessions and real Android/iOS PWA install/offline recovery.
