Optional cloud sync: threat and conflict model

Status: design gate only. ArcanaScreen does not currently transmit workspace data.

Threat model

  • Protected assets: screen content, campaign notes, identities, links, settings and recovery history.
  • Primary risks: token theft, accidental public sharing, malicious imports, provider compromise, rollback and metadata leakage.
  • Required controls: explicit opt-in, least-privilege provider scope, encrypted transport, revocable credentials, local export, deletion and a visible sync log.
  • Secrets must never be stored inside exported screen payloads or browser logs.

Conflict model

  • Every screen needs a stable id, schema version, revision id, device id and modification timestamp.
  • Disjoint tool changes may merge by tool id. Concurrent edits to the same tool create a recoverable copy; they are never silently overwritten.
  • Deletes use tombstones until every known device observes them. Clock time alone cannot determine causality.
  • Before upload, the user sees the provider, account, scope and exact data classes. Offline work remains fully supported.

Activation criteria

A provider can be implemented only after privacy review, conflict tests across two devices, credential revocation tests, data deletion verification and an explicit product decision based on user demand.
